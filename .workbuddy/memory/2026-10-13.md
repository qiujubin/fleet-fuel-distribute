## 今天遇到两次环境问题（都不是数据问题），排查过程值得记住

### ⚠️ 1) 本机代理没开 → 取数全失败（首次运行）

第一次跑 `run_daily.py`，⓪ 步直接报 `ConnectionRefusedError [WinError 10061] 目标计算机积极拒绝`，
流程按设计**安全中止（未做任何写入）**。

排查：
- `curl` 失败 exit=7；`ping` 100% 丢包（但 ICMP 可能被云防火墙挡，不能单凭这个判断）
- **关键证据**：环境变量里有 `HTTP_PROXY=http://127.0.0.1:7897/`、`HTTPS_PROXY=...`、
  `WORKBUDDY_PROXY_SOURCE=system` —— 而该端口**没有进程在监听**（用户本地代理客户端没开）
- 裸 IP `/dev/tcp` 直连测试：`223.5.5.5:443` ✓、`114.114.114.114:53` ✓、**`159.75.177.27:5180` ✓**
  → 接口服务器本身是好的、可直连
- `curl --noproxy '*'` → **HTTP 200，0.08 秒**拿到数据 ✓

**解法**：跑流程时清掉代理环境变量即可 ——
```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy -u ALL_PROXY -u all_proxy \
  python run_daily.py
```
（`fetch_api.py` 目前依赖 `urllib` 默认代理行为，所以会踩这个坑。**已告知用户，等他决定要不要
在 fetch_api.py 里改成"先直连、失败再走代理"的兜底**——没擅自改。）

⚠️ 顺带一个教训：**不要在这个环境里 `env | grep xxx`** —— 会 dump 出几十万字节的
`CODEBUDDY_MCP_CONFIG`，白烧 token。查环境变量请只取具体名字。

### ⚠️ 2) 第二次运行：考核表被 WPS 占用（只读）→ ①④⑤ 全失败

取数成功了，但 ① 报「以下文件正被打开：油耗考核10月_宏.xlsm」，④⑤ 同样。
排查进程（`Get-CimInstance Win32_Process`）：占用者是**上一次失败运行留下的
`wps.exe/et.exe ... /Automation -Embedding` 实例**（09:14:58 启动），不是用户手动开的。
等了一会儿再测 `Workbooks.Open(..., 0, False)` → `ReadOnly=False` → 占用已自行释放，重跑成功。
（目录里那两个 `~$油耗考核10月_宏.xlsm`（7-31）、`~$维修保养2026.xlsx`（8-03）是陈旧残留，不阻塞。）

**经验**：脚本失败退出时 COM 实例的 `Quit()` 可能来不及/静默失败，短时间内会占住文件。
**失败后不要立刻重跑，先测一次可写性再动手。**
